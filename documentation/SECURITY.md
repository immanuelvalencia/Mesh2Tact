# Security Policy

## Supported versions

Security fixes are applied to the latest code on the repository's active development branch. No older release line is currently maintained.

## Reporting a vulnerability

Do not open a public issue for a vulnerability. Use GitHub's private vulnerability reporting feature on the repository's **Security** tab. If private reporting is unavailable, contact the repository owner through the contact method shown on the owner's GitHub profile and request a private channel.

Include:

- the affected version or commit;
- the operating system and installation method;
- reproduction steps or a minimal proof of concept;
- the expected and observed impact; and
- any suggested mitigation.

Do not include credentials, private datasets, or identifiable camera data. Please allow the maintainers time to reproduce and address the report before public disclosure.

## Scope

Reports involving unsafe file handling, arbitrary code execution, dependency compromise, path traversal, untrusted model or configuration loading, and unintended disclosure of local data are in scope. General scientific limitations and model accuracy concerns should be reported as ordinary issues.
